# Mixed-action retrieval repair

The first CQ130 build and evidence-integrity checks passed, but original and configured retrieval were both 12/14. The purchases-versus-wants question missed P82–84, P89–90 and P95; the play-plus-purchases question missed P76. Full manually reviewed answers were correct, but retrieval did not supply all their evidence. first-verification.json and first-triage.json preserve these failures. The six frozen fresh questions independently passed their first retrieval run before any code change (36–67 of 95 windows returned).

Ranked hypotheses were: single-intent routing dropped a clause; lexical result limits crowded out supporting lore; or stale/missing mappings prevented recovery. Targeted triage reproduced the misses and showed the first question routed to price_evaluation and the second to acquisitions. Existing fresh-index and proof checks ruled out stale/missing data. The lexical term budget was not truncated. Reduced synthetic questions reproduced the same lost-state pattern through the real answer_evidence seam.

The diagnosing-bugs workflow required a red-capable loop before changing code. Two new tests were run before the fix: the evidence-route test failed for both reduced questions, while the advice guard passed. They require explicit purchase/want or purchase/play evidence plus denial/qualification records, without adding the unrelated action state. The shared helper now recognizes explicit multi-state history questions ahead of price-only routing and unions the requested typed action evidence. It includes mentioned-state qualifications so denied purchases and nonplay are not discarded, preserves episode scope and source text, exposes the requested states, and rejects advice/wishlist framing. It does not invent facts or use episode-specific titles, source windows or answer keys.

The same two tests then passed in 0.092 seconds. The complete original CQ130 scenario returned 14/14 under both unchanged wordings after rebuilding. No question, required window, answer or forbidden inference was weakened. Shared-code hashing correctly made previous indexes stale; they must be rebuilt, not have their human review bindings renewed. An archive-guard refusal during that transition is preserved in repair-verification.json; repair-local-verification.json is the successful local feedback loop, not final archive acceptance.

The initial 233-test suite passed before the discovered repair. A final full shared suite and previous-collection build/gate/original-question sweep are required afterward. No temporary debug instrumentation was added. The synthetic regression fixtures remain intentional tests, not claims of archive-wide semantic accuracy. Mixed queries can still return broad evidence, especially because mentioned-state records include diverse qualifications; precision is a documented limitation, not concealed by recall passes.

The first post-fix full suite caught one genuine scope regression: “What are the top three games Tyler wanted to buy?” had been misread as a mixed action request. The existing test was not changed. The helper now requires explicit conjunction/contrast and declines wanted-to/planned-to and finish-collecting constructions. New negative examples preserve that boundary; the two focused action tests and all eighteen selection tests pass. final-shared-suite.log preserves the initial 234/235 result; settled-shared-suite.log records the final rerun. No successful result is inferred until that rerun completes.

Settled outcome: 235/235 shared tests pass; twenty previous batch gates, 643/643 available original questions and pilot19/19 pass after index rebuilds. The full unchanged CQ130 original/configured cases pass14/14 and first/final fresh6/6. No debug instrumentation remains. The correct cause was single-intent routing of explicit multi-state questions, not missing extraction or an insufficient lexical term budget.
